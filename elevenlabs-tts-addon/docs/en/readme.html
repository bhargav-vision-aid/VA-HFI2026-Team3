ElevenLabs TTS

An NVDA add-on that uses the ElevenLabs streaming AI text-to-speech service. Tuned for Indian users — voices and languages relevant to the Indian subcontinent are surfaced first.

First-time setup

  1. Install the .nvda-addon file. Restart NVDA when prompted.
  2. Get a free key from elevenlabs.io.
  3. Open NVDA+N → Preferences → Settings → ElevenLabs TTS.
  4. Paste your API key. Click Test API key to verify.
  5. Click OK. Then under Preferences → Settings → Speech, pick "ElevenLabs Streaming AI" as the synthesizer.

What the settings panel controls

SettingWhat it does
API keyRequired. Stored in NVDA config.
Test API keyCalls the API right now and plays a short phrase. Confirms the key works.
Default voiceComes from your live ElevenLabs library. Use Refresh voice list to reload it.
ModelFlash v2.5 (fastest), Turbo v2.5 (balanced, default), Multilingual v2 (best quality, supports non-English).
Translation languageTarget language for the NVDA+Shift+T gesture. Indian languages only: Tamil, Hindi, Telugu, Marathi, Bengali, Kannada, Malayalam, Gujarati, Punjabi, Urdu.
Default rate / volume / pitchStarting values for the on-the-fly settings ring.
Pre-warm cacheFetches every common single character for the current voice and saves it to disk. Eliminates first-time latency for letter-by-letter reading.
Clear cacheDeletes the on-disk audio cache.

Live controls while ElevenLabs is the active synthesizer

ShortcutAction
NVDA+Ctrl+Right/LeftCycle through rate / voice / volume / pitch.
NVDA+Ctrl+Up/DownAdjust the current setting (or switch voice).
NVDA+Shift+TTranslate the currently selected text into the configured Indian language and speak it. Rebindable under NVDA Menu > Preferences > Input gestures > ElevenLabs TTS.

Translation (1.4.0+)

Select text in any app — a paragraph in your browser, a sentence in Notepad, a row in a chat window — then press NVDA+Shift+T. The selection is sent to Google's free public translation endpoint and the result is spoken aloud in your configured Indian language. The target language is whatever you picked under Translation language in the settings panel.

Translation uses the eleven_multilingual_v2 model regardless of your saved Model setting, so Indian languages are pronounced correctly even if you normally use Turbo for English.

No translation API key is required — Google's free endpoint is used. If translation stops working it usually means Google has rate-limited your IP for the day; wait a few hours and try again.

On-disk audio cache

Short utterances (≤ 8 characters) are saved as raw PCM at %APPDATA%\nvda\elevenlabsTTS_cache\. Cached audio plays in under 50 ms instead of the ~500 ms network round-trip. The cache is keyed by (voice, output format, text) — switching voice triggers a fresh recording for that voice. Cache is capped at 100 MB and evicts least-recently-used files.

Troubleshooting

SymptomWhere to look
No audio at allCheck API key in settings; click Test API key; check NVDA log for ElevenLabs: lines.
"free tier not available for this voice"Click Refresh voice list — your tier may have changed which voices are available.
Lag after long idleShould not happen in 1.2.1+. If it does, log it (Tools → View log) and report the line.
Indian-language text sounds badSet Model to Multilingual v2. Only Hindi and Tamil are officially supported; other languages are experimental.
